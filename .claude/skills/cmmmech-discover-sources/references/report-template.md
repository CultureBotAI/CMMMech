# Source investigation report template

Copy this structure into the requested report destination and fill it with
observed evidence. Mark unknown or unchecked items explicitly; omit irrelevant
subsections with a reason. Do not retain empty example rows as findings.

# CMM source investigation: topic

## Scope and provenance

- UTC timestamp; researcher/reviewer identity.
- Repository revision, branch and relevant working changes.
- Research question, material identities/forms, mechanisms, jurisdiction/list
  editions, date range, source types and chosen bounds.
- Existing records/reports checked; hidden/ignored search coverage and exclusions.

## Candidate inventory

| Candidate key | Canonical URL/DOI/accession and version | Source role | Material/organism coverage | Evidence actually inspected | Decision and reason |
|---|---|---|---|---|---|

Use decisions such as pursue, context only, defer, duplicate, or reject. Acquisition
state (metadata only, full text read, supplement checked, dataset sampled,
previously acquired artifact rechecked, blocked) is separate from scientific
fitness. Distinguish original acquisition from this round's inspection.
Link mirrors/supplements to their parent
study and explain whether a dataset adds independent observations or reuses them.

## Source assessments

Repeat for each substantive candidate:

- Bibliographic/owner identity, version/release and stable identifiers.
- Proposed claim and exact supporting section/table/figure/rows.
- Material form, organism resolution, assay conditions/controls and scale,
  when relevant; distinguish observation, fitted result and inference.
- Dated criticality authority and mapping, when relevant.
- Supporting, contradictory and limiting evidence; correction/retraction search
  coverage; details that remain unchecked.
- Dataset format, schema/data dictionary, sample and advertised coverage, keys,
  units/denominators, missing data, join feasibility and update/version policy.
- Access route, license/terms URL and reuse limits; unknown is a valid finding.
- Retained files: source URL, acquisition time, path, version and checksum.
- Candidate CMMMech fields/records and prerequisites for defensible curation.

## Priorities and handoff

Rank next actions with evidence, coverage benefit, effort and dependencies.
Separate candidates ready for claim-level curation from sources needing access,
identity, licensing or experimental clarification. Link existing records that
may need reassessment. Do not label a record accepted solely from this search.

## Limits and unresolved questions

State inaccessible sources, unsearched scope, bounded negative findings,
uncertainties and the concrete evidence needed to resolve them. Record report
checks actually performed; do not claim record validation or independent review
unless it happened.
